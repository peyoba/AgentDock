# AgentDock 立项需求分析

> 历史调研文档（已被后续决策部分取代）：本文保留早期问题分析和外部终端方案背景；当前正式范围与验收标准以 `docs/PROJECT_REQUIREMENTS.md`、`DECISIONS.md` 和 `PROJECT_PROFILE.md` 为准。

> 项目定位：可视化的 Claude / Codex 多配置终端启动器，让用户同时运行多个互不干扰的 AI CLI 实例，每个实例拥有独立 endpoint / API key，同时可自由进入同一个或不同项目目录。

## 1. 项目背景

Claude CLI、Codex CLI 等工具通常依赖环境变量、全局配置文件、`auth.json`、`config.toml`、shell alias 或手动切换 endpoint / API key。单账号单端点可以接受，但当用户需要同时运行多套配置时，传统“全局切换配置”的方式会互相影响。

目标场景：

```text
Claude 1 -> Endpoint A -> Key A -> 项目 X
Claude 2 -> Endpoint B -> Key B -> 项目 X
Claude 3 -> Endpoint C -> Key C -> 项目 Y
Codex 1  -> Endpoint D -> Key D -> 项目 X
Codex 2  -> Endpoint E -> Key E -> 项目 Z
```

核心原则：**不是切换全局配置，而是为每个新终端单独注入一套独立运行环境。**

## 2. 目标用户

- 同时使用多个 Claude / Codex CLI 的开发者
- 使用 AnyRouter、OpenRouter、官方 API、公司代理、自建 API 网关的用户
- 需要比较不同模型/供应商效果的用户
- 需要多个 AI agent 同时在一个项目里协作的用户

## 3. 核心需求

### 3.1 API Profile 管理

用户可以可视化新增、编辑、删除 API Profile。

每个 Profile 包含：

- 名称
- 工具类型：Claude / Codex
- Endpoint / Base URL
- API Key
- 默认模型
- 协议类型：Anthropic / OpenAI Responses / OpenAI Chat / 自定义
- 是否启用本地代理/适配器
- 环境变量模板
- 备注

API key 应保存到本机加密 vault，不应明文保存在普通配置文件中；macOS Keychain 仅作为旧数据迁移/兼容 adapter。

### 3.2 Workspace 管理

用户可以保存多个项目目录。

每个 Workspace 包含：

- 项目名称
- 本地路径
- 默认分支
- 默认启动命令
- 是否 Git 项目
- 是否允许共享目录并发
- 是否建议创建 worktree

API Profile 与 Workspace 解耦：一个 Profile 可以打开任意 Workspace，一个 Workspace 也可以同时被多个 Profile 打开。

### 3.3 独立终端启动

点击启动后，App 打开一个新终端窗口或标签页，并只给这个终端注入该配置的运行环境。

支持终端目标：

- Terminal.app
- iTerm2
- Warp
- Ghostty
- 自定义终端命令

Claude 启动方式：

```text
注入 ANTHROPIC_BASE_URL、ANTHROPIC_AUTH_TOKEN / ANTHROPIC_API_KEY 等环境变量
cd <workspace-path>
claude
```

Codex 启动方式：

```text
注入 CODEX_HOME=~/.agentdock/codex-profiles/<profile-id>
写入该 CODEX_HOME 独立 config.toml/auth.json
cd <workspace-path>
codex
```

### 3.4 并发运行管理

App 显示当前启动过的会话：

- 工具类型
- Profile 名称
- 工作目录
- 启动时间
- 终端类型
- 进程状态
- 使用的 endpoint
- 是否共享工作目录

可选操作：聚焦终端、复制启动命令、查看启动日志、重新启动、停止进程。

### 3.5 同目录并发安全提示

多个 agent 可以进入同一个项目目录，但文件系统共享，可能出现同时修改同一文件、git 状态共享、依赖安装互相影响等问题。

检测到多个会话使用同一目录时，提示：

```text
当前已有多个 AI 会话在此目录运行。如果它们同时修改同一个文件，可能产生冲突。
```

提供选项：继续共享目录 / 创建独立 Git worktree。

## 4. 非目标 / 边界

MVP 不做复杂 API 网关、请求日志、成本统计、模型自动路由、fallback、API key 轮换等高级功能。这些可作为后续版本能力。

## 5. 技术可行性

完全可行。

- Claude：通过每个终端独立环境变量隔离 endpoint / key。
- Codex：通过每个 Profile 独立 `CODEX_HOME` 隔离 endpoint / key / auth / history / config。
- Workspace：通过启动前 `cd <workspace-path>` 控制，与 API Profile 独立组合。

## 6. 产品原则

1. 不改全局配置
2. 每个终端独立环境
3. API key 不明文落盘
4. Profile 和 Workspace 解耦
5. 允许同项目并发，但提示冲突风险
6. 简单启动优先，高级路由后置
7. 用户能看见每个终端到底用了哪套配置
