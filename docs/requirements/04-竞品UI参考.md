## 2. 重点参考项目

### 2.1 CC Switch / ccswitch

仓库：

- `farion1231/cc-switch`
- `SaladDay/cc-switch-cli`
- `Laliet/cc-switch-web`
- `luckybilly/cc-switch-helper`
- `HamGuy/CCSwitch`
- `terranc/ccsc`
- `XueshiQiao/CCSwitcher`

代表界面：

![[assets/ui-references/ccswitch-desktop-main.png]]

![[assets/ui-references/ccswitch-desktop-add-provider.png]]

![[assets/ui-references/ccswitch-web-main.png]]

![[assets/ui-references/ccswitch-web-config-provider.png]]

可借鉴点：

- 顶部按工具分组：Claude / Codex / Gemini。
- Provider 使用大卡片列表展示，信息密度适中。
- 「Currently Using」状态标签清楚。
- 添加 provider 时先选 preset，再填写名称、官网、endpoint、key。
- Web 版的供应商配置弹窗很适合 AgentDock 的 Profile 编辑弹窗。
- `cc-switch-helper` 明确支持“不同终端使用不同 provider”，方向与 AgentDock 最接近。

不适合直接照搬的点：

- 多数 ccswitch 工具偏“切换当前配置”，AgentDock 要避免全局切换。
- AgentDock 需要在启动时绑定 Workspace，这一点 ccswitch 主界面没有突出。
- AgentDock 需要显示并发 Sessions，而不是只显示当前使用 provider。

### 2.2 Claude Code Router Desktop / CCR

仓库：`musistudio/claude-code-router`

代表界面：

![[assets/ui-references/claude-code-router-dashboard.png]]

可借鉴点：

- 深色 Dashboard 很适合展示运行状态、可用性、请求数、token、成本。
- 左侧导航清晰：Overview / Providers / Agent Config / Routing / API Keys / Models / Logs / Settings。
- 顶部显示本地 endpoint，有助于让用户知道当前网关地址。
- Provider 卡片带健康状态、余额、额度进度条。

不适合直接照搬的点：

- CCR 偏本地网关和路由中心，AgentDock 应该优先是“终端启动器”。
- Dashboard 信息量较大，MVP 可先轻量化。

### 2.3 ccNexus

仓库：`lich0821/ccNexus`

代表界面：

![[assets/ui-references/ccnexus-light.png]]

可借鉴点：

- 统计卡片直观：端点数、总请求数、总 token 数。
- 顶部端口显示明显。
- 端点列表、日志、启动器在同一页，有“控制台”感觉。
- 中文用户体验友好。

不适合直接照搬的点：

- 视觉风格偏重、渐变明显；AgentDock 可以更接近 macOS 原生简洁风。
- 它更偏端点轮询代理，不是 Profile + Workspace 组合启动器。

### 2.4 Codex Switch

仓库：`kuangre123/codex-switch`

代表界面：

![[assets/ui-references/codex-switch.png]]

可借鉴点：

- 单页表单非常直接，适合新用户理解。
- 当前状态卡片清楚显示 provider、模型、地址、API key 摘要。
- 保存按钮明确：“保存配置并重启”。
- 适合作为 AgentDock 的“简单模式”参考。

不适合直接照搬的点：

- 它是全局切换器，不适合多个终端并发隔离。
- AgentDock 不应以“保存并重启全局工具”为主，而应以“Launch New Terminal”为主。

仓库：`freestylefly/wesight`

代表界面：

![[assets/ui-references/wesight-live-workspace.png]]

![[assets/ui-references/wesight-agent-engines.png]]

## 3. 对 AgentDock 的 UI 建议

### 3.1 主界面结构

建议融合 ccswitch 的轻量卡片 + CCR 的状态概念：

```text
左侧：Profiles / Workspaces / Launch / Sessions / Settings
顶部：Quick Launch + 当前运行数量
主区：Profile + Workspace 组合启动
右侧或下方：Running Sessions
```

### 3.2 Profile 卡片

参考 ccswitch：

```text
[图标] Claude - AnyRouter A       🟢 Ready
      https://xxx.example.com
      Model: claude-sonnet-4
      Key: sk-***abcd
      [Launch] [Edit] [Duplicate] [Test]
```

### 3.3 Launch 组合器

AgentDock 独有，必须比竞品更突出：

```text
Profile:   [Claude - AnyRouter A v]
Workspace: [AgentDock 项目 v]
Mode:      [共享目录] [Git worktree] [临时副本]
Terminal:  [iTerm2 v]
Task:      [可选任务标签]
[Preview Env] [Launch Terminal]
```

### 3.4 Sessions 页面

参考 CCR/ccNexus 的状态卡片，但围绕“终端实例”而不是“请求统计”：

```text
🟢 Claude - AnyRouter A
Workspace: /path/project-a
Endpoint: https://xxx
Started: 21:30
Terminal: iTerm2
[Focus] [Restart] [Copy Launch Command] [Stop]
```

### 3.5 视觉风格

推荐：

- macOS 原生浅色为默认，支持深色。
- 卡片式列表参考 CC Switch。
- 状态和统计参考 CCR。
- 配置弹窗参考 cc-switch-web。
- 不做过重渐变，避免 ccNexus 那种工具感过强。

## 4. AgentDock 与竞品差异点

| 产品 | 更偏向 | AgentDock 可借鉴 | AgentDock 差异 |
|---|---|---|---|
| CC Switch | Provider 切换 | 卡片列表、preset、添加弹窗 | 不做全局切换，做并发终端隔离 |
| cc-switch-helper | 多终端 provider | 同终端隔离方向 | AgentDock 做可视化 + Workspace 管理 |
| CCR | 本地网关/路由 | Dashboard、状态、provider 管理 | AgentDock 不依赖统一网关 |
| ccNexus | 端点轮询代理 | 统计卡片、日志 | AgentDock 核心是启动器 |
| Codex Switch | Codex 单工具切换 | 简洁表单、当前状态 | AgentDock 支持多工具多实例 |
| WeSight | AI Agent 工作台 | 任务/代码变化/agent 引擎选择 | AgentDock MVP 不做完整工作台 |

## 5. 推荐 AgentDock MVP UI 方向

第一版不要做成大而全工作台，建议：

1. **Home / Quick Launch**：常用 Profile + Workspace 组合。
2. **Profiles**：像 CC Switch 一样管理 provider 卡片。
3. **Workspaces**：保存项目目录。
4. **Launch**：AgentDock 的核心组合启动器。
5. **Sessions**：显示正在运行的终端实例。

一句话：

> 用 CC Switch 的易用性，加上 CCR 的状态感，再加入 AgentDock 独有的 Workspace + 并发 Session 管理。
