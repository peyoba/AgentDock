# AgentDock 技术架构方案

## 结论

AgentDock 推荐采用：

```text
Electron + React + TypeScript + xterm.js + node-pty
```

这是最适合当前产品目标的架构：

- 要做内嵌终端
- 要同时运行多个 Claude / Codex 会话
- 要每个会话注入独立 endpoint / API key / CODEX_HOME
- 要快速做出可用 MVP
- 要尽量接近 VSCode / Cursor 的终端体验

## 为什么选 Electron，而不是 SwiftUI / Tauri

### 1. Electron 最适合内嵌终端

VSCode / Cursor 这类产品的内置终端本质上也是：

```text
xterm.js + PTY
```

Electron 生态里最成熟的组合是：

```text
xterm.js 负责终端显示
node-pty 负责创建伪终端并运行 shell / claude / codex
```

这条路成熟、资料多、坑少，最适合 AgentDock MVP。

### 2. SwiftUI 原生更漂亮，但终端难度更高

SwiftUI 没有官方 TerminalView。要实现内嵌终端，需要：

```text
SwiftTerm + forkpty
```

可行，但输入法、ANSI 渲染、快捷键、滚动、resize、多会话管理都需要更多定制。对 MVP 来说风险偏高。

### 3. Tauri 更轻，但 PTY 集成不如 Electron 成熟

Tauri 可以用：

```text
React + xterm.js + Rust PTY
```

包体更小，但 PTY 层、事件桥接、多会话管理需要自己写更多 Rust/IPC 逻辑。后续可以考虑，但不是最快 MVP 路线。

## 总体架构

```text
AgentDock Electron App
├── Renderer：React + TypeScript
│   ├── Profiles UI
│   ├── Workspaces UI
│   ├── Launch UI
│   ├── Sessions UI
│   └── xterm.js terminal tabs
│
├── Main Process：Electron + Node.js
│   ├── Session Manager
│   ├── Profile Manager
│   ├── Workspace Manager
│   ├── Secret Storage Adapter（本机加密 vault 为主，Keychain 仅 legacy 迁移/适配）
│   ├── PTY Manager：node-pty
│   └── Config Generator
│
└── Local Storage
    ├── app config / profiles metadata
    ├── workspace metadata
    ├── session history metadata
    ├── per-profile CODEX_HOME directories
    └── API keys in local encrypted vault
```

## 核心模块

### 1. Profile Manager

负责管理接口配置：

```text
Profile ID
名称
工具类型：Claude / Codex
Endpoint / Base URL
默认模型
协议类型
Vault secret reference
额外环境变量
Codex HOME path
```

API key 不直接保存在普通配置文件中；新保存密钥进入本机加密 vault，配置只保存引用和脱敏状态。旧 macOS Keychain adapter 仅用于迁移/兼容。

### 2. Workspace Manager

负责管理项目目录：

```text
Workspace ID
名称
路径
默认启动模式
Git 状态
默认终端模式
备注
```

Workspace 与 Profile 解耦。

### 3. Session Manager

负责运行会话：

```text
Session ID
Profile ID
Workspace ID
PTY process
启动时间
运行状态
环境变量快照
终端标签页
```

每个 session 都是独立 PTY，因此 endpoint/key/CODEX_HOME 互不影响。

### 4. PTY Manager

基于 `node-pty`：

```text
createSession(profile, workspace)
write(sessionId, input)
resize(sessionId, cols, rows)
kill(sessionId)
```

Claude session：

```text
export ANTHROPIC_BASE_URL=...
export ANTHROPIC_AUTH_TOKEN=...
cd <workspace>
claude
```

Codex session：

```text
export CODEX_HOME=~/.agentdock/codex-profiles/<profile-id>
cd <workspace>
codex
```

### 5. Terminal Renderer

基于 `xterm.js`：

- 每个 session 一个 terminal instance
- 支持标签页
- 支持分屏作为后续能力
- 支持复制/粘贴
- 支持 resize
- 支持 ANSI 颜色
- 支持 scrollback

## 数据存储建议

MVP 阶段：

```text
~/Library/Application Support/AgentDock/config.json
~/Library/Application Support/AgentDock/workspaces.json
~/Library/Application Support/AgentDock/sessions.json
~/Library/Application Support/AgentDock/secrets.vault.json
~/.agentdock/codex-profiles/<profile-id>/
```

后续如果数据复杂，再迁移 SQLite。

## UI 架构建议

MVP 界面应简化，不做复杂 Dashboard。

```text
左侧：配置 / 工作目录 / 会话 / 设置
主区：启动器
底部或右侧：运行会话标签
```

内嵌终端建议默认以标签页方式收纳：

```text
[Claude · AnyRouter A] [Codex · OpenAI] [Claude · Kimi]
```

每个标签页内部是一个 xterm.js 终端。

## MVP 范围

第一版建议直接支持内嵌终端，但功能保持克制：

- Profile 增删改查
- Workspace 增删改查
- API key 存本机加密 vault
- Claude 内嵌终端启动
- Codex 内嵌终端启动
- 多 session 标签页
- 每个 session 独立环境变量
- Codex 每个 profile 独立 CODEX_HOME
- 关闭/重启 session
- 环境预览

暂不做：

- 请求统计
- 成本统计
- 模型自动路由
- API gateway
- 多端点 fallback
- 复杂分屏
- 团队同步

## 技术风险

### 1. Claude / Codex TUI 兼容性

需要重点测试：

- Ctrl+C
- Esc
- 方向键
- 粘贴长文本
- 中文输入
- 终端 resize
- 大量输出

### 2. macOS 签名和权限

Electron app 打包后需要处理：

- node-pty native module
- notarization
- vault 读写权限与 legacy Keychain 迁移兼容
- shell path 获取

### 3. 环境变量加载

不要完全依赖用户 shell rc 文件。应提供：

- 默认 PATH 探测
- 用户自定义 PATH
- 启动前环境预览

## 最终建议

AgentDock 应该走：

```text
Electron + React + TypeScript + xterm.js + node-pty
```

产品形态是：

```text
轻量配置启动器 + 内嵌终端标签页 + 多会话管理
```

不是 API 网关后台，也不是完整 IDE。

这条路线最利于 AI Coding 快速实现，也最接近 VSCode / Cursor 内置终端的成熟方案。
